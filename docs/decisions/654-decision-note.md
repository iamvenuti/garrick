# Decision note

**The concept.** A decision note is the short written decision a pull request must link when it adds a concept to the docs.

**What it touches.** It sits under Instructions, beside `AGENTS.md` and the `.local` files, and it is read by the release process, not by the assistant at work in a workspace.

**What was measured.** Nothing could be measured before it existed. It follows three units (the unit a wall protects, the piece of work, the maintenance finding) that were each built before they were decided and then reworked several times.

**What would show it is wrong.** A release where concepts were added with a note that nobody read, or a check that stopped a pull request which only fixed wording: either one means the rule is too weak or too strict, and we would change it.
